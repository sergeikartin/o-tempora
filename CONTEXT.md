# Same Sky

A read-only, continuously zoomable visualization of world history — People, Conflicts, and Milestones lanes, hardcoded ahead of time.

## Language

**Conflict Category**:
The curator-assigned classification for Conflicts entries (`Conflict`/`ConflictEvent.category`) — `war, war-of-independence, revolution, rebellion, coup-d-etat, military-operation`. Assigned by the curator at `data/raw/conflicts-curated.raw.json` authoring time, not derived from a Wikidata `?type` claim (see **Container** below for how the lane is sourced). Conflicts-only; Milestones has its own separate `Milestone Category` (below). No longer drives a color — the timeline's merged Conflicts+Milestones lane renders every Conflict in one flat color instead (`CONFLICT_COLOR` in `packages/web/src/shared/config/conflict-color.ts` — lives in `shared/config`, not the `widgets/timeline-canvas` rendering code, since the sidebar's Conflicts & Milestones filter pill swatch needs it too, same reasoning as `MILESTONE_CATEGORY_GROUP_COLORS`; the old Conflict Category Palette this field used to drive is retired, see `packages/web/docs/design-tokens.md`), so a Conflict still reads as one visual group next to Milestones' own multi-color palette. Does not determine `Conflict` vs. `ConflictEvent` shape — see **Container**. Has no equivalent to **Milestone Category Group** — Conflicts carry no color-driving grouping at all, so in the sidebar's shared Conflicts & Milestones filter (one multi-select pill list, same shape as Region/Occupation Domain — see that entry below), "Conflicts" is just one more pill alongside the 3 Milestone Category Group pills, swatched with the flat `CONFLICT_COLOR`, rather than a per-category or per-group breakdown of its own.
_Avoid_: Category (bare — ambiguous with Milestone Category), occupation domain, tag, type (for this specific field)

**Container**:
A top-level, parent-less curated `Conflict` that other Conflicts rows nest under via the optional `parentId` field (on both `Conflict` and `ConflictEvent`, always resolving to another row's `id`, which is always a `Conflict`) — e.g. the Napoleonic Wars containing the Peninsular War as a real, independently-curated entity rather than a free-text label. Nesting is capped at 3 levels (Container → level 2 → level 3) and validated at Output (`buildConflicts` in `write-datasets.ts`); a violation drops the offending row rather than publishing it. `Conflict` vs. `ConflictEvent` shape is itself decoupled from `Conflict Category` and from curator input — decided at Output by whether the row's Wikidata enrichment resolved both a start and an end date (`Conflict`) or only one (`ConflictEvent`); a row resolving no date at all is dropped. See `.scratch/wars-curated-source/spec.md` and `packages/data-pipeline/docs/adr/0009-wars-sourced-from-curated-list-plus-container-nesting.md`.
_Avoid_: parent war, umbrella war/conflict (for this specific mechanism — use Container)

**Tagline**:
A Person/Conflict/ConflictEvent/Milestone's short Wikidata `schema:description` claim (`TimelineEntry.tagline`) — one line, e.g. "American physicist". Required for publish: an entity with no resolvable Tagline is dropped (`write-datasets.ts`). Live-fetched per-QID via Wikidata SPARQL for all three lanes, including Milestones (previously curator-authored only) — no curated-text fallback, the same convention People/Conflicts already used. Rendered in `DetailPanel` as the subtitle under the entity name.
_Avoid_: Description (this field's old, pre-split name), subtitle, blurb

**Description**:
A Person/Conflict/ConflictEvent/Milestone's Wikipedia lead-paragraph prose (`TimelineEntry.description`) — fetched live from Wikipedia's REST summary API `extract` for the entity's English Wikipedia article, English-only, uncapped length. Optional: absent when no English Wikipedia article resolves, in which case `DetailPanel` renders **Tagline** alone. Distinct from Tagline, which is a short Wikidata subtitle, not prose — the two are separate fields, not a fallback pair.
_Avoid_: Summary, extract, blurb (bare — ambiguous with Tagline)

**Milestone Category**:
Milestones' own curator-assigned taxonomy — 22 leaf values (e.g. `science-theory`, `medicine-health`, `public-health`, `commerce-finance`; full list in `packages/shared-types/src/index.ts`'s `MilestoneCategory`). A separate enum from Conflict Category — disjoint source (hand-curated, not a Wikidata `?type` claim) and disjoint values. `public-health` (Black Death, 1918 Spanish flu, COVID-19, US FDA, Hygiene, Great Irish Famine) was split out of `medicine-health` on 2026-08-13 so the pandemic/public-health-administration/disaster items could land in a different **Milestone Category Group** than medicine-health's treatments/vaccines/procedures. That same day, `media-culture` was split out of `communication` (Penny Black, BBC Television Service launch, Facebook, Workers Leaving the Lumière Factory, View from the Window at Le Gras); `architecture-design` was retired and merged with `infrastructure` into a new `landmarks` category; and `exploration` was renamed `expedition`, with its craft/technology items (Sextant, Sputnik 1, Vostok 1, Voyager 1, International Space Station) moved to `everyday-technology`/`transportation`. Every leaf value belongs to exactly one Milestone Category Group (below).
_Avoid_: Category (bare), conflict category (for this specific field), Discovery Category (this field's old, pre-rename name)

**Milestone Category Group**:
The 2-value grouping above Milestone Category's 22 leaf values, driving the Milestones lane's color palette: `science-innovation` ("Science & Innovation": science-theory, medicine-health, communication, transportation, everyday-technology, food-agriculture, energy-industry), `social-culture` ("Social & Human Culture": public-health, media-culture, landmarks, infrastructure, expedition, society-administration, culture-arts, religion-mythology, environment-geology, commerce-finance, social-movements, sports-entertainment, philosophy-education, law-jurisprudence, archaeology-anthropology). Formalized as `MilestoneCategoryGroup` + a `MILESTONE_CATEGORY_TO_GROUP` map in `packages/shared-types` — the single canonical source both the Milestones lane's color mapping (`packages/web/src/widgets/timeline-canvas/options.ts`) and the sidebar's shared Conflicts & Milestones filter read from. Replaced an earlier 3-value grouping (`knowledge-culture`/`technology-industry`/`society-governance`) on 2026-08-13 with this coarser Science-vs-Social split, worked out against the actual per-category milestone counts to land close to evenly split — see `docs/adr/0002-milestone-category-group-conflicts-blanket-toggle.md`'s addendum. The sidebar filter itself is one multi-select pill list (`ConflictsMilestonesFilterValue` in `packages/web/src/shared/config/conflicts-milestones-filter.ts`) spanning these 2 groups plus a UI-only `'conflicts'` sentinel — same "one flat list, empty means unfiltered" shape as Region/Occupation Domain, not a separate control per lane. Conflicts has no leaf-category or group taxonomy of its own — see **Conflict Category**.
_Avoid_: Category Group (bare — Milestones-only, doesn't apply to Conflicts), Milestone Group

**Occupation Domain**:
Pantheon 2.0's own occupation grouping for People entries — `sports, institutions, arts, humanities, science-technology, business-law, public-figure, exploration`. A separate enum from both Conflict Category and Milestone Category, sourced from Pantheon rather than Wikidata. Drives the Occupation Domain Palette in `packages/web/docs/design-tokens.md`. The same pills that show this palette double as the filter control: clicking a pill toggles that domain in/out of the People lane (multi-select, OR within the filter — matching any selected domain is enough; no pills active means unfiltered).
_Avoid_: Category, occupation category, conflict category, milestone category (for this specific field), Legend (retired term for these pills — "Legend" implied a decorative color key; they're a filter now, referred to plainly as the Occupation Domain filter/pills)

**Region** (filter):
A single region filter — the UN M49 geoscheme's 22 sub-regions (`northern-europe, southern-europe, eastern-europe, western-europe, eastern-asia, south-eastern-asia, southern-asia, central-asia, western-asia, northern-africa, western-africa, middle-africa, eastern-africa, southern-africa, northern-america, central-america, caribbean, south-america, australia-and-new-zealand, melanesia, micronesia, polynesia`) — spanning all three lanes, one shared taxonomy (`Region[]` on `Person`, `Conflict`, `ConflictEvent`, and `Milestone` alike, no per-lane translation). Conflicts and Milestones read it straight off their `regionTags` field, curated at Wikidata-enrichment time off each entity's country Q-ID(s), historical-polity-aware (a historical polity resolves to whichever sub-region its territory corresponds to today, not a successor state's name). People's tags come from Pantheon's birth/death country instead, present-day-location rather than historical-nationality. One shared control across all three lanes, not per-lane like Fame Score. Multi-select, OR within the filter; no regions selected means unfiltered. An entity with no region tags at all (some Conflicts ship with `regionTags: []`) is excluded whenever any region filter is active, since it can't match a selected value.
_Avoid_: geography filter, area filter, macro-region/sub-region (retired distinction — one taxonomy now, not two)

**Lifespan** (rendering context):
A Person's birth-death range bar on the People lane's timeline — the visual object built from `Person.startYear`/`endYear` in `map-to-items.ts`'s `mapPeopleToItems`. Distinct from `TimelineEntry`'s general start/end range shape, which every lane (People, Conflicts, Milestones) shares.

**Fame Score**:
`TimelineEntry.fameScore` — the numeric field driving each lane's manual UI filter floor (`FAME_SCORE_BOUNDS`/`FameScoreFilters`) and each lane's vertical row position (`assignRows` in `map-to-items.ts`, processed fame-descending rather than chronologically): the highest-fame items land in row 0, which each lane then places at whichever of its edges sits against the shared Year Axis — the bottom of People, the top of the merged Conflicts+Milestones lane — so importance radiates outward from that axis in both directions. Computed independently per lane, never blended across lanes: People uses raw Pantheon HPI (0–100); Conflicts & Milestones use a log-normalized blend of Wikidata sitelinks and Wikimedia pageviews, one shared 0–100 scale across both lanes (`packages/data-pipeline/docs/adr/0010-blend-sitelinks-and-pageviews-for-wars-discoveries-fame-score.md`) — that shared scale is what lets Conflicts and Milestones compete directly for the same rows in the merged lane. Still never drives zoom or marker size, and row position is a distinct concern from z-order (which element paints on top when two things visually overlap at the same spot).
_Avoid_: Importance score, significance score, popularity score

**Lane**:
One of the three top-level content tracks — People, Conflicts, Milestones — each with its own fetch/score/tag/output path (`packages/data-pipeline/docs/adr/0001-wars-discoveries-people-separate-lanes.md`). Consolidated from the earlier "Wars & Conflicts"/"Events & Inventions" display names and their mismatched internal names (`wars`/`discoveries` CLI values, `events-curated.raw.json`, `fetchEventsEnrichment`) onto one canonical name per lane, used everywhere — UI copy, `fetch`'s `--lane=<value>` CLI selector (`people`/`conflicts`/`milestones`), types, and file names (`packages/data-pipeline/docs/adr/0013-rename-lanes-to-conflicts-and-milestones.md`). The timeline's display layer renders Conflicts and Milestones together in one mixed, fame-ranked visual row (`ConflictsMilestonesLane`) — a rendering-only grouping, not a fourth Lane or a merge of the two: each keeps its own fetch/score/tag/output path above unchanged.
_Avoid_: track, Wars & Conflicts, Events & Inventions, wars, discoveries, events (as a lane name)

**Minimap**:
The log-scaled, mirrored-ridge area-sparkline that replaces the timeline's scrollbar — People's Row Depth curve above a center baseline, Conflicts+Milestones' inverted below it, drawn across the full pannable range (`PAN_MIN_YEAR` to present) so users can see ahead of panning where a region will demand many more rows. Computed client-side from already-loaded lane data (no pipeline artifact) and recomputed live as the fame-score filters change; also the pan/zoom control itself — click jumps, dragging the overlaid viewport rectangle pans, hovering surfaces exact per-series Row Depth via tooltip. A thin, non-interactive strip of century tick marks runs along its top edge — ticks at every century boundary across the full pannable range, labels thinned via minimum-pixel-spacing once adjacent labels would collide (`packages/web/docs/adr/0004-density-minimap-replaces-scrollbar.md`).
_Avoid_: Mountain Profile (this term's retired prior name — the "ambiguous with a literal miniature-thumbnail rendering" concern that motivated the original name didn't hold up in practice), density chart, sparkline (bare)

**Row Depth**:
The number of vertical rows a lane's items need at a given point in time to render without overlap — a location's Row Depth is `max(row index) + 1` among items covering it. Each item's own row index (`TimelineEntry.row`) is computed once by data-pipeline's Output stage (`row-assignment.ts`'s `assignRows`), against the *entire* lane at once, and shipped as data — not derived client-side (`docs/adr/0005-row-assignment-moves-to-the-pipeline.md`; `packages/web`'s `compactRows` only narrows that precomputed row down to whatever's currently visible, never recomputes it). Drives both a lane's live rendered height and, computed at the Reference Scale, the Minimap's per-series height.
_Avoid_: lane height (the rendered pixel consequence, not this count), row count, stack depth

**Reference Scale**:
The fixed `pixelsPerYear` (`defaultPixelsPerYear()`, derived from `DEFAULT_VISIBLE_YEARS`) the Minimap packs items against to compute Row Depth across the whole pannable range — deliberately decoupled from the user's live zoom, so the Minimap reflects the app's default 120-year opening view rather than a worst-case (most-zoomed-out) or arbitrary scale. The same numeric scale data-pipeline's `row-assignment.ts` packs each entry's permanent Row Depth row against, both sides reading `packages/shared-types`' `REFERENCE_SCALE_PIXELS_PER_YEAR` (data-pipeline imports it directly; `packages/web`'s `options.ts` keeps deriving its own copy live via `defaultPixelsPerYear()` so it still auto-follows `DEFAULT_VISIBLE_YEARS`/`FALLBACK_VIEWPORT_WIDTH_PX`, with `options.test.ts` asserting the two stay equal — `docs/adr/0005-row-assignment-moves-to-the-pipeline.md`'s addendum).
_Avoid_: default zoom (the opening viewport itself; this is the packing scale reused from it), base scale

**Locale**:
Which of the app's two languages — English (base locale, default) or Russian — a given page load renders, resolved at runtime from the URL: `/` for English, `/ru/` for Russian (Paraglide's `url` strategy, `packages/web/docs/adr/0009-runtime-locale-switch-replaces-per-locale-builds.md`). One build, one shared JS/CSS bundle for both (`packages/web/vite.config.ts`); the Locale only determines which UI chrome/taxonomy string catalog entries display (Paraglide JS, `packages/web/messages/{en,ru}.json`) and which lane dataset files get fetched (`people.tier0.json` vs. `people.tier0.ru.json`, etc. — see **Field Fallback** and **Payload Tier**), via a locale-keyed dynamic import in `src/app/locale-datasets.ts`. No inline bilingual display within one page load. The two locales cross-link via a home-level switcher (`Sidebar`'s language-switcher link, pointing at the sibling's default view, not a deep link) that does a full navigation, not an in-place switch.
_Avoid_: language build (superseded term — there's no longer a per-language build), language mode, translation (bare, for this concept)

**Field Fallback**:
The per-field rule the data pipeline applies once, at Output time, when building a lane's Russian dataset file (`people.tier0.ru.json`/`people.tier1.ru.json`/etc., siblings of the English `people.tier0.json`/`people.tier1.json`/etc. — see **Payload Tier**): use the Russian value (`name`/`tagline`/`description`) if the pipeline's Wikidata/`ru.wikipedia.org` fetch resolved one for that field, else fall back to the English value (`write-datasets.ts`'s `resolveField`/`resolveOptionalField`). Baked into the Russian file at pipeline output time — `packages/web` never resolves a fallback itself, at build or runtime. Row *inclusion* (which entities exist in the dataset at all) is a separate, earlier decision, made once off the English fetch results only, regardless of language — Field Fallback only ever changes which language's text ends up in an already-included row, never whether the row exists; both language files always share the identical entity set.
_Avoid_: translation fallback, default language, English fallback (as the primary term — this is a general per-field mechanism, not English-specific, even though English happens to be the only fallback language today)

**Data Depth**:
A two-position UI preset switch — `Mainstream < Deep Cut` — that sets all three lanes' numeric Fame Score floors (`FameScoreFilters`) at once. Framed as a depth dial, not a fame-elitism dial: `Mainstream` (People 88, Conflicts 82, Milestones 82) is the shallowest slice and equals the app's existing launch default; `Deep Cut` (People 80, Conflicts 64, Milestones 55) digs deeper by lowering the floor and surfacing more, lower-fame entries. Purely a UI convenience layered on top of the existing per-lane numeric floor — picking a level just writes new numbers into the same inputs a user could type by hand, and hand-editing a number afterward drops the switch to an unhighlighted custom state (the numbers no longer match any preset row). Distinct from the old pipeline-side "Fame Tier" gating mechanism removed in ADR 0003, which explicitly rejected fixed tier points as slider presets — Data Depth doesn't reintroduce that, it's a shortcut for the continuous floor that already exists. See **Payload Tier** for an unrelated, pipeline-side concept that happens to reuse these same threshold numbers.
_Avoid_: Fame Tier (retired term, different mechanism — pipeline gating, not a UI preset), Fame Level (earlier working name for this switch, dropped for the depth framing), Curated/Expanded/Full (retired three-tier level names, collapsed to two in the 2026-08-18 grill-with-docs session)

**Payload Tier**:
A per-lane, per-locale split of the pipeline's Output stage into two files — `<lane>.tier0.json` (entries at or above the **Data Depth** "Mainstream" thresholds — People 88, Conflicts 82, Milestones 82) and `<lane>.tier1.json` (the remainder, down to the pipeline's existing floor — People HPI≥75, Conflicts/Milestones unfiltered). Purely a network-loading boundary: Tier 0 loads eagerly and gates first paint; Tier 1 loads separately (idle-deferred, skipped on slow/save-data connections) and merges into the in-memory dataset once it resolves. Deliberately independent of Data Depth despite sharing threshold values today — which tier an entry shipped in never affects whether it renders; that's still decided entirely client-side by the Fame Score filter (ADR 0003).
_Avoid_: chunk (bare — ambiguous with a general Vite/JS bundle chunk), Deep Cut chunk / mainstream chunk (would conflate this with the Data Depth UI preset), Fame Tier (retired term, ADR 0003 — pipeline-side density gating, a different mechanism from this loading-only split)

**Search**:
A live text query, matched case-insensitively as a substring against an entry's Name and Tagline in whichever Locale is active, spanning all three Lanes at once. Narrows only within what the current Data Depth floor, Region, Occupation Domain, and Conflicts & Milestones filters, and whatever Payload Tier data has loaded, already permit — never a broader lookup that reaches past them (`docs/product-scope.md`'s "search outside the current Data Depth/fame-score floor" exclusion; `packages/web/docs/adr/0010-search-stays-inside-active-filters-and-payload-tiers.md`). Picking a result is equivalent to clicking its rendered mark: pans and opens `DetailPanel`, nothing more.
_Avoid_: filter (bare — Search narrows within the existing filters, it isn't one of them), lookup, autocomplete (describes the UI widget, not this domain concept)
