Root `CONTEXT.md`: rewrote the **Conflict Category** entry (curator-assigned now, not Wikidata-`?type`-derived; six values, not nine; doesn't determine shape) and added a new **Container** entry covering the `parentId` mechanism, the 3-level depth cap, and the enrichment-driven shape rule, cross-linking the spec and the new ADR. No `packages/data-pipeline/CONTEXT.md` or root `CONTEXT-MAP.md` exist yet in this repo (per `docs/agents/domain.md`, these are created lazily by `/domain-modeling`, not scaffolded speculatively) — Container went into the existing root `CONTEXT.md` instead, this repo's actual glossary today. New ADR: `packages/data-pipeline/docs/adr/0009-wars-sourced-from-curated-list-plus-container-nesting.md`, mirroring ADR 0008's three-paragraph shape (problem, decision, consequences) and explicitly calling out where this migration diverges from Discoveries' precedent (enrichment-sourced not curator-authored description/dates; no reusable bootstrap tooling) plus the real QID-quality finding from the live run (ticket 06). Verified no remaining `battle`/`siege`/`peace-treaty` references anywhere in `packages/*/src` outside of test fixture *names* (e.g. "Battle of Gettysburg" as a `WarEvent.name`, not a `category` value) and the intentional historical-documentation comments in `shared-types/src/index.ts` and `options.ts`; confirmed the web filter-chip UI derives its category list from the shared `CONFLICT_CATEGORIES` constant rather than a separate hardcoded list, so no filter-UI code change was needed beyond ticket 01's type-level shrink.
