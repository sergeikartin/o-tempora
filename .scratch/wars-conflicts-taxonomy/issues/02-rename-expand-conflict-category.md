# Rename Category to ConflictCategory and expand to the 9-value taxonomy

Type: task
Status: resolved

## Question

`Category`/`CATEGORIES` (`packages/shared-types/src/index.ts`) is used exclusively by `War`/`WarEvent` today (Discoveries has its own `DiscoveryCategory`, People has `OccupationDomain`) — just for WarsLane.tsx's fill color, no filter/legend UI reads it. Its current 7 values (science, politics, art, philosophy, war, exploration, religion) were never fully populated by the wars pipeline (only "war" and "politics" were ever produced by `EVENT_TYPE_CATEGORIES`).

Land this rename + expansion:

1. Rename `Category` → `ConflictCategory`, `CATEGORIES` → `CONFLICT_CATEGORIES`, in `packages/shared-types/src/index.ts` and every import site (`War.category`, `WarEvent.category`, `data-pipeline/src/transform/event-type-categories.ts`, `output/write-datasets.ts`, `web/src/widgets/timeline-canvas/options.ts`'s `CATEGORY_COLORS`, `WarsLane.tsx`, and their tests).
2. Replace the old 7-value list entirely with the 9 confirmed values: `war`, `battle`, `siege`, `military-operation`, `revolution`, `rebellion`, `coup-d-etat`, `war-of-independence`, `peace-treaty` (armistice was dropped — see the "Per-category sitelink fame-tier floors" ticket's answer; it yields 0 items at any floor consistent with the other categories) (pick a consistent casing convention — the existing `DiscoveryCategory` values use kebab-case, e.g. `science-theory`, `everyday-technology` — match that).
3. Assign each new value a hex color in a renamed `CONFLICT_CATEGORY_COLORS` (`options.ts`), following the same hue-optimization-against-every-existing-color methodology documented at `.scratch/events-inventions-curated-source/issues/01-discovery-category-color-palette.md` (there are now 15 existing People/Domain + Discovery colors plus whatever's kept from the old 2 Wars colors to stay clear of). Update `packages/web/docs/design-tokens.md`'s Occupation Category Palette section to match.
4. Update `CLAUDE.md`'s Language section (`**Category**:` entry) to describe `ConflictCategory` instead.
5. Update `options.test.ts`'s "CATEGORY_COLORS has one entry per Category" test (rename, same shape check) and any other test fixtures asserting the old 7-value list or old color count.

This ticket only touches the type/contract/color layer — it does not touch what actually gets tagged onto each row (that's the tag-events/event-type-categories rewrite ticket, which depends on this one existing first).

## Answer

Landed. `Category`/`CATEGORIES` renamed to `ConflictCategory`/`CONFLICT_CATEGORIES` in `packages/shared-types/src/index.ts`, replaced the 7-value list with the 9 confirmed values (kebab-case: `war`, `battle`, `siege`, `military-operation`, `revolution`, `rebellion`, `coup-d-etat`, `war-of-independence`, `peace-treaty`); every import site updated (`War.category`/`WarEvent.category`, `data-pipeline/transform/event-type-categories.ts`, `data-pipeline/transform/tag-events.ts`, `data-pipeline/output/write-datasets.ts`, `web/shared/types/index.ts`'s re-export, `web/widgets/timeline-canvas/map-to-items.ts`, `options.ts`, `WarsLane.tsx`, `options.test.ts`).

Colors: `CATEGORY_COLORS` → `CONFLICT_CATEGORY_COLORS` (`options.ts`), 9 new hex values generated by hue-optimized farthest-point-in-largest-gap placement against the 18 existing People/Domain (8) + Discovery (10) hues (proportional-gap allocation, not the earlier session's naive greedy sampling, which degraded to ~8.6° worst-case separation late in the sequence — the gap-proportional method holds a tighter floor). Achieved min separation ~8.5°–18° from existing colors (tighter than Discovery's ~11° precedent since there are now 27 colors sharing one hue circle); the two closest pairs (`military-operation` vs. neighbors, `war-of-independence` vs. neighbors) lean on S/L instead of hue alone for extra separation, same technique `design-tokens.md`'s Domain palette already uses for `public-figure`/`science-technology`. War-family categories (war/battle/siege/military-operation) grouped into warm red-orange-yellow hues; the rest into cooler green-blue-violet hues:

`design-tokens.md`'s "Occupation Category Palette" renamed to "Conflict Category Palette" with the new table; its "Occupation Domain Palette" prose corrected too (was already stale: claimed `OccupationDomain`'s `exploration` value overlapped with the Wars taxonomy, but that overlap is actually with `DiscoveryCategory`, unrelated to this rename). Root `CONTEXT.md`'s Language section: `**Category**` entry replaced with `**Conflict Category**` (Wars & Conflicts-only now, corrected from its stale "and Events & Inventions" scope claim) plus a new `**Discovery Category**` entry, since the old entry was already conflating two taxonomies that split apart in an earlier effort — fixing the rename properly required disentangling both.

Scope held to the type/contract/color layer as specified: `data-pipeline/transform/event-type-categories.ts`'s `EVENT_TYPE_CATEGORIES` table still collapses onto the old 2-bucket scheme (its `"politics"` literal-mapped entries) — untouched, since retagging onto the new 1:1 scheme is "Retag events onto ConflictCategory 1:1"'s job, which is blocked by this ticket for exactly that reason. This leaves 4 anticipated `tsc` errors confined to that one file (`"politics"` not assignable to `ConflictCategory`) until that ticket lands — `npm run typecheck --workspace packages/data-pipeline` shows only those 4, `--workspace packages/web` is clean, and both workspaces' full test suites pass (111 web / 102 data-pipeline) since the runtime string values are unaffected, only the type declaration. `npm run lint`/`lint:boundaries --workspace packages/web` also clean.
