# Dataset flow

## Fetch

- People start with the Pantheon 2.0 CSV snapshot, decompressed with `seek-bzip`. Conflicts and Milestones start with the checked-in `<lane>-curated.raw.json` lists. Curators assign categories and parent IDs. Milestones also accept an English/Russian `displayName`, a `fameSource` QID to score instead, and a `date` override (`{year, month?, endYear?, endMonth?, approximate?}`). Approximate dates render with “ca.”. [Label and fame overrides](adr/0018-curated-milestones-can-override-label-and-borrow-fame.md) · [Date overrides](adr/0019-curated-milestones-can-override-their-date.md)
- Batched Wikidata SPARQL enriches the listed QIDs. All three lanes use its English and Russian names and Taglines and P18 images. Conflicts and Milestones also get country QIDs, sitelinks, article URLs for the pageviews basket and dates. Conflicts use P580/P585 for start and P582 for end. Milestones resolve start from a priority-ordered list and use P582 for end. An end date makes the entity period-shaped. [Date resolution](adr/0015-milestones-taxonomy-expansion-and-date-fetching.md) · [Date shapes](adr/0016-milestones-can-be-period-shaped.md) · [Localized labels](adr/0017-name-sourced-from-wikidata-label-plus-russian-wikipedia-dependency.md)
- Wikimedia Commons `imageinfo` supplies image credits and licenses. Wikipedia REST supplies optional Descriptions through sequential English and Russian passes at about two requests per second. Fetch writes `<lane>-image-attribution.raw.json`, `<lane>-pageviews.raw.json` and `<lane>-wikipedia-extracts.raw.json`, with a `.ru.raw.json` counterpart for extracts. [Wikipedia extracts](adr/0011-tagline-description-split-and-wikipedia-rest-dependency.md)
- A full fetch processes all lanes. `--qids` refreshes matching entries in place, reuses the local Pantheon snapshot and ignores QIDs absent from the source lists. [Lane-scoped fetch](adr/0012-lane-scoped-fetch.md)

## Score and tag

- People use Pantheon HPI, occupation and birth/death countries. Conflicts and Milestones retain the curated categories, derive Region tags from Wikidata country QIDs and share a log-normalized sitelink/pageview Fame Score. Scoring and tagging are locale-independent. Correct rankings and tags in Transform and rebuild. [Scoring](adr/0010-blend-sitelinks-and-pageviews-for-wars-discoveries-fame-score.md)
- Evidenced Person date corrections in `person-date-corrections.ts` check the expected baseline and feed both dataset output and Profile inputs. A changed baseline fails for review. The raw Pantheon snapshot stays intact. [Date corrections](adr/0025-person-dates-can-have-evidenced-corrections.md)

## Build and publish

- English fields determine entity inclusion. Both locales share the same entity IDs, English-derived Slugs and permanent rows. Use Russian name, Tagline and Description where available and fill missing fields from English. Rows use the widest label across both locales, with People packed separately from the combined Conflicts and Milestones. [Slugs](adr/0020-entity-slugs-are-pipeline-assigned-and-unique-across-lanes.md) · [Row assignment](../../../docs/adr/0005-row-assignment-moves-to-the-pipeline.md)
- Output writes four Detail Level deltas per lane and locale using the shared Fame Score floors. It normalizes images to HTTPS, rewrites Commons `Special:FilePath` to `Special:Redirect/file`, and omits image URL and attribution for IDs in `IMAGE_DENYLIST`. [Detail Level config](../../../docs/config-variables.md)
- Profile Output joins by Wikidata QID (People get it from their Pantheon row). It resolves Connections in authored order using localized target names and target Slug, lane and Detail Level. It drops repeated, self-referential and missing targets. Passage sources retain anchors on absolute HTTP(S) URLs without credentials. Output validates shipped markup (balanced `**bold**` only) and fails if the Profile’s entity is absent. Approval and locale rules are in the [Profile workflow](profiles.md).
- Run `build-data` to regenerate `data/output/`. Run `publish-data` to copy the datasets and replace the Profiles directory in `shared-types`. [Output and publish](adr/0004-output-and-publish-are-separate-steps.md)
