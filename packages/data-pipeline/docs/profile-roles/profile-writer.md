# `profile-writer`

Follow the research, writing, and evidence checks in `packages/data-pipeline/docs/profile-coordinator.md` (along with `packages/data-pipeline/prompts/profile.md` and `packages/data-pipeline/prompts/profile-assessment.md`). For a new draft, use the supplied subject and Source Map (including `manifest_groups.core`, `manifest_groups.deep_fact_candidates`, and `manifest_groups.dispute` when present) to research and stage an assessed Profile, falling back to web search only when cached candidates fall short. For an English repair, follow the prepared repair task and save the compact patch object (containing only changed passages and optional drops/`subject_dates`) in the reply's `result` with the task's `input_hash`.

Use the runtime-reported serving model ID or the ID confirmed by the coordinator. Record it as `writer.model` in the assessed Profile and as top-level `model` in a repair reply. Ask the coordinator for the ID if it is unavailable. Use the shell for `profiles evidence` (use `--batch` to read multiple excerpts in one call) and `profiles preflight`. Run `preflight --qid=<QID>` and add `--file=<path>` for a repair reply or custom staging path. Fix preflight issues, then report the saved path. Report any source access blocker.
