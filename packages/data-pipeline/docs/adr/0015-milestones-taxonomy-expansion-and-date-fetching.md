# Milestones taxonomy expands to 20 categories; year/month move from curator-authored to live-fetched

A second AI-sourced candidate list of ~94 milestones was merged into the existing 121-entry curated list (`data/raw/milestones-curated.raw.json`). Its QIDs were almost entirely wrong — 83 of 94 resolved to an unrelated Wikidata item (e.g. the candidate id for "Great Wall of China" actually resolved to "Grand Canal") — so every new entry was re-resolved to its correct QID by name against live Wikidata, and any candidate with no matching Wikidata item or no live date-property claim on any of the 10 candidate properties (see below) was dropped rather than guessed at (67 of the 94 survived). That list also introduced 10 new `MilestoneCategory` values (`culture-arts`, `religion-mythology`, `environment-geology`, `commerce-finance`, `social-movements`, `sports-entertainment`, `philosophy-education`, `law-jurisprudence`, `archaeology-anthropology`, `architecture-design`) alongside the original 10 — folded into the taxonomy as-is rather than remapped into the existing categories, since the only mandatory downstream cost turned out to be 10 new hex values in `MILESTONE_CATEGORY_COLORS` (`packages/web/src/widgets/timeline-canvas/options.ts`); everything else (validation, tests, rendering) is already generic over `MILESTONE_CATEGORIES`.

Separately, the curated file's old hand-typed `year`/`dateProperty`/`source`/`tagline` fields are gone — the file is now `{id, name, category}` only, matching `conflicts-curated.raw.json`'s shape. `year`/`month` are resolved live per QID by `fetchMilestonesEnrichment`, the same "curated file carries no date of its own" sourcing Conflicts already used (ADR 0011's tagline/description split did this for `tagline`; this does it for the date too). Milestones cover a much wider spread of entity shapes than Conflicts (inventions, discoveries, publications, institutions, spacecraft launches, structures...), so no single Wikidata property reliably holds "the" date the way Conflicts leans on P580/P585 — `queries/milestones-enrichment.ts` instead COALESCEs across the same 10 properties the old hand-typed `dateProperty` field enumerated (P575, P571, P577, P580, P585, P569, P606, P619, P729, P1619), in that priority order, using the same p:/psv:/BestRank statement-value-node pattern Conflicts uses for precision.

## Consequences

`TaggedMilestone.year` (and the newly added `TaggedMilestone.month`) are now optional, matching `TaggedConflict` — a milestone whose QID resolves to no claim on any of the 10 date properties gets dropped at Output (`write-datasets.ts`'s `validateEventRow`) instead of failing to parse a curated `year` that no longer exists. The priority order isn't universally correct per-property-type (e.g. a multi-year span's P585 "point in time" can land on an arbitrary point within the span rather than its start, and a published work's P571 "inception" can predate its actual publication) — two such cases were caught and hand-corrected during this merge (California Gold Rush, Philosophiæ Naturalis Principia Mathematica) but the general fallback chain is not guaranteed to always pick the most natural date for every future curated entry; a curator re-checking a new entry's resolved year against its Wikidata claims remains worthwhile.
