# packages/web — Timeline Rendering (D3)

<!-- How the three lanes render on the shared D3 timeline. Read before touching TimelineCanvas or a lane widget. -->

- All D3 rendering config for the three lanes is scoped to `widgets/timeline-canvas/` — layout/scale config, item-mapping, and per-lane rendering are kept as separate concerns within that widget, not spread elsewhere.
- Years are plain numbers end-to-end for positioning — BCE negative, astronomical numbering (year 0 is 1 BCE) — positioning logic never touches a month. Every year shown to the user must go through the shared BCE/CE display formatter — never a raw number, never a duplicated BCE/CE check at the call site.
- Date precision can include a month, but month is only ever surfaced in the detail panel (member dates, the overlap line), never used for positioning.
- The three lanes share one horizontal-scroll container; that container's native scroll position *is* the time-axis sync across lanes — there's deliberately no cross-lane scroll listener or reentrancy guard. Each lane manages its own vertical row-overflow independently.
- Zoom is one shared scale/state across all three lanes (they must stay in lockstep), clamped to a fixed min/max year-span.
- **Detail Level gates entity density manually — zoom controls only the time-scale**, not which entities render (`packages/web/docs/adr/0003-manual-fame-filter-replaces-zoom-tier.md`). Filtering is client-side against the data-pipeline's already-broad output — no re-ranking.
- **The Year Axis is deliberately plain HTML/CSS, not SVG/D3** like the rest of the widget — tick marks are CSS background gradients, never a per-tick DOM node (`docs/adr/0012-year-axis-as-plain-css-ruler.md`). Decade labels are windowed to the visible scroll range and omitted below a minimum on-screen spacing to avoid collision at low zoom.
- **Span Bands and the Overlap Band are drawn inside the zebra layer** (`SelectionBands.tsx`) — a full-height wash per **Selection** member (Period = band, PointInTime = 1px hairline) and one stronger band for the shared span, positioned with the live `xScale`. The zebra layer already sits behind every lane, spans the full scroll width and follows the zoom animation's group transform, so the bands stay registered with the marks through a zoom. They draw only for a Selection — never on hover — and never dim or move other marks. The Overlap Band is at least 4px wide (`OVERLAP_BAND_MIN_WIDTH_PX`), centred on its span. Both the band and the detail panel's overlap line come from one `computeOverlap` call (`shared/lib/entity/overlap.ts`) in `app/App.tsx`, and a sr-only sentence beside the Viewport Range heading describes the bands to assistive technology.
- **An Entity Link's arrival fits the viewport to the union of the Selection's spans** (`arrivalFitViewport` in `options.ts`): +10% each side, clamped to the zoom limits, sized to the canvas minus the 340px desktop drawer, with the union's midpoint centred in the uncovered part. Clicks and Search picks never change zoom. While a Selection is open on desktop the scroll width grows by the drawer's width as empty space past the present, so recent spans can be panned clear of the drawer; the Viewport Range heading never reads past today.
- **Century marks are one ink motif drawn three times** — a lifted, bordered tab in the Year Axis label row, the axis's own bold century tick, and a 1px seam running through both lanes (and the translucent ruler bar itself) — all sharing `--color-border-emphasis`, including the Minimap's own century-strip tick. Century labels are static like the other Year Axis labels (no pin-to-viewport-edge behavior) — jumping to a period stays the Minimap's job.
- **Viewport Range has its own strip above the lanes** — a Fraunces heading (`ViewportRange.tsx`, 72px tall on desktop, 48px on mobile) showing the visible span of years (`CONTEXT.md`), updated live from the scroll position. The zoom controls overlay the strip's top-right corner. The strip has no divider; it sits on the page parchment.
- **The Top Bar sits above the canvas in normal flow** (`TopBar.tsx`, 56px on desktop, two rows at the mobile breakpoint), so the canvas wrapper takes the remaining height instead of the full viewport. The desktop detail panel starts below it (`--top-bar-height`), keeping Search, Filters and Help reachable while a Selection is open. People labels pin to the scroll container's edge, so the full-width canvas needs no offset.
- **The Minimap is a floating card** — inset 12px from the canvas edges as a card (ledger surface, hairline border, 12px radius, ink-tinted shadow); the page background (`body`) shows in the gutter around it.
- **Phones get a Scrubber instead of the Minimap** — a 24px strip (`Scrubber.tsx`) directly under the Viewport Range, mounted exactly where `useIsMobileViewport()` omits the Minimap, in normal flow at the top so the bottom Selection sheet never covers it. It reuses the Minimap's century tick strip (`centuryStripTicks` in `minimap.ts`) over the full pannable range and shows the Viewport Range as a thumb; position only, no density. A tap on the track eases the viewport there (the Minimap's jump path); dragging the thumb pans 1:1 with the pointer. Both are expressed as a centre year and clamped to the pan bounds by `TimelineCanvas`. The thumb follows scrolling from the same `scrollLeft` state as the Viewport Range, and during a pinch or zoom animation `TimelineCanvas` writes it straight through the `ScrubberHandle` (`zoomedViewportYears`), so no marks re-render per frame. Its hit area is a 44px target (extended upward only), over a 16px minimum visible width. The `.scrubberSlot` holds the 24px from first paint, since hydration assumes desktop.
- **People labels pin to the viewport's left edge** — a person's name label normally starts at its bar's start, but while the bar began left of the viewport, `pinnedLabelX` (`map-to-items.ts`) slides the label right to stay readable. It leaves with the bar's end and stops short of the next bar in its row (`labelRoomX2`), so it never collides with another label. `TimelineCanvas` calls `PeopleLane`'s `pinLabelsToViewport` from the same scrollLeft mirror that pans the lanes; only labels whose pinned position changed are written.
- **People lane fades at its top edge while rows are scrolled out of view** — a CSS mask on `.peopleLane`, toggled by a scroll listener in `TimelineCanvas.tsx` (`data-has-more-above`), so it signals more rows above and disappears once the lane is scrolled to its top.
- Conflicts and Milestones render directly off pre-split, lane-scoped data from the data-pipeline — no client-side category filtering to route entries between lanes.
- Colliding items in every lane are row-stacked using one shared greedy interval-stacking algorithm, sized in pixel-space rather than year-space, since on-screen label width isn't proportional to underlying date range. A row is a **static per-item identity** — computed once against the full dataset at a fixed reference scale, never the live zoom or the currently-filtered set — that each lane then compacts down to whatever it's actually rendering, so an item's row never changes just because of a filter or zoom change (`packages/web/docs/adr/0007-static-row-assignment-replaces-live-per-render-packing.md`).
- Each lane's D3 join keys off literal marker classes, never CSS-Module classes — CSS Modules are styling-only and must never be used as D3 join selectors. A marker class can be shared across lanes, so code querying it (including tests) must scope to the owning lane's `<svg>`, not assume one per page.
- There are no native SVG tooltips; a click-to-open detail panel shows entity details. Entity lookup happens at click time against the already-in-memory dataset, not precomputed per rendered item.
- **Wheel, drag and keys.** Ctrl/Cmd+wheel and a trackpad pinch (browsers send it as ctrl+wheel) zoom under the cursor through the same group-transform path as button zoom and touch pinch: marks stay drawn at the starting `pixelsPerYear`, and the year under the cursor stays fixed. `pixelsPerYear` commits once, 150ms after the last wheel event, and the wheel listener is a native non-passive one so only these events lose the browser's page zoom. A plain wheel scrolls the lane's rows; Shift+wheel pans; a horizontal wheel or trackpad swipe is left to the browser's native scroll and momentum. A mouse drag coasts on release and stops at the pan bounds; under `prefers-reduced-motion` it doesn't coast. `←`/`→` pan a tenth of the viewport (half with Shift) and `+`/`=`/`-` zoom about the viewport centre, from a document-level handler that ignores text fields, selects, the Detail Level group and any open modal. The People and Conflicts+Milestones lanes are keyboard-focusable regions, so their rows scroll with the arrow keys. A Shift/Ctrl/Cmd-click on a mark reports it as additive to `onEntityClick`, which `app/` turns into a Selection toggle. Mouse-drag panning is gated to mouse pointers specifically, so touch keeps native swipe-to-scroll.
