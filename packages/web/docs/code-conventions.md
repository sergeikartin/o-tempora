## Code Standards

- FSD layer and public-API boundaries are enforced by Steiger in CI — a violation fails the build, not a style suggestion.

### React (mini-FSD)

- Layers: `shared → features → widgets → app` (`entities`/`pages` deliberately omitted — single-domain, single-page app). A layer may only import from layers below it.
- Each slice exposes one public `index.ts`; other code never reaches into a slice's internals.
- Functional components only. D3's DOM manipulation is client-only — never assume it can server-render.
- Filter/selection state lives in the feature slice it belongs to; no global state folder.

### Styling

- CSS Modules only, no global stylesheets beyond one base/reset file.
- No hardcoded hex values — all color/typography/radius come from tokens (`docs/design-tokens.md`), as CSS custom properties. `app/global.css`'s `:root` block wires the color and radius tokens (not yet typography — no webfont is loaded); `widgets/sidebar/`'s own CSS Module consumes them. Exception: `widgets/timeline-canvas/`'s D3 rendering core and its lane CSS Modules (`PeopleLane.module.css`, `WarsLane.module.css`, `EventsLane.module.css`, `TimelineCanvas.module.css`, `YearAxis.module.css`), plus `shared/config/occupation-domain-colors.ts`'s `DOMAIN_COLORS` (the same provisional per-domain hex values, hoisted there because both `widgets/timeline-canvas` and `widgets/sidebar`'s Legend swatches need them) — all provisionally inline hex pending ticket 05 (see Timeline Rendering below) — everywhere else, hardcoded hex is a real violation.
- Occupation category colors are the single source of truth for People-lane lines, Events-lane marker borders, and the matching filter chip.
- Shape carries Period vs. PointInTime, the same rule across all three lanes: a rounded-cap line for a real duration (People's lifespans/reign-periods, Wars & Conflicts' ranges), a dot for a single moment (Wars & Conflicts' WarEvents, Events & Inventions). Person vs. event is instead carried by lane, label position (People's label above its line; Wars & Conflicts and Events & Inventions below their marker), and color palette (occupation domain vs. category) — never by color alone, which still means occupation category/domain only.

### Timeline Rendering (D3)

- All D3 rendering config lives in `widgets/timeline-canvas/` (`options.ts` for layout constants/colors/the shared `xScale`/zoom math, `map-to-items.ts` for pure `Person`/`War`/`Discovery` → render-item mapping plus the shared row-assignment function, one component per lane: `PeopleLane.tsx`, `WarsLane.tsx`, `EventsLane.tsx`).
- Years are plain numbers end-to-end for *positioning* (BCE negative, ISO/astronomical numbering — year 0 is 1 BCE) — `xScale`/row-stacking never touch a month, only each entity's `.year`. `shared/lib/dates.ts` keeps only `today()` (for the live upper time bound), which still returns `Temporal.PlainDate` since callers just read its `.year`. Every year shown to the user is display-formatted as "N BCE"/"N CE" through the one shared `shared/lib/format-year.ts` utility (`formatYear`) — never a raw interpolated number, and never a duplicated BCE/CE check at the call site.
- Dates carry optional month precision in `shared-types`' `YearMonth` (`{ year, month? }`, month absent means the source data is only certain to the year) — `Period` (`{ start, end? }`, `end` absent means ongoing) for a real duration, `PointInTime` (`{ at }`) for a single moment; see `packages/shared-types/src/index.ts`. Only *tooltips* read month — `format-year.ts`'s `formatYearMonth(yearMonth)` renders "March 1815"/"1815" (falling back to `formatYear` alone when month is absent), used by `map-to-items.ts`'s `mapPeople` tooltip (lifespan + each reign-period sub-tooltip). `mapWars`/`mapDiscoveries` don't currently interpolate a date into their tooltip text at all (name only, plus `partOfWarName` for Wars & Conflicts), so month never surfaces there — nothing to convert.
- People, Wars & Conflicts, and Events & Inventions are three lane sections stacked vertically inside **one shared-horizontal-scroll container** (`TimelineCanvas.tsx`'s `scrollContainer`) — that container's native scroll position *is* the time-axis sync across all three lanes, no `rangechange`-style listener or reentrancy guard. Each lane section keeps its own independent `overflow-y: auto` region for row overflow (People needs it — 11 rows over 49 people); a lane's wrapper div is given an explicit inline `width` (the shared `xScale`'s `totalWidth`) wider than the scroll container, which is what drives the shared horizontal scrollbar.
- Zoom is a numeric `pixelsPerYear` state in `TimelineCanvas.tsx`, shared by all three lanes since they share one `xScale`; the +/- buttons call `zoomIn`/`zoomOut` from `options.ts`, clamped to the bounds implied by `ZOOM_MIN_YEARS`/`ZOOM_MAX_YEARS` (10-500, `shared/config/viewport.ts`) at the container's current width.
- **Sidebar fame-score filters gate entity density manually** — zoom controls only time-scale (`packages/web/docs/adr/0003-manual-fame-filter-replaces-zoom-tier.md`; supersedes the zoom-coupled Fame Tier system, ADR 0002, outright). `widgets/sidebar`'s Filters section renders one raw-`fameScore` numeric floor per lane via `features/filter-by-fame-score`'s `FameScoreFilters` (bounds/defaults in `shared/config/viewport.ts`'s `FAME_SCORE_BOUNDS: Record<FameScoreLane, { min, max, default }>` table — defaults match the old CORE tier's values); session-only state lives in that feature's `useFameScoreFilters` hook, called once in `App.tsx` and threaded as props to both `Sidebar` and `TimelineCanvas`. `TimelineCanvas.tsx` takes the feature's `FameScoreValues` as one plain prop and filters `people`/`wars`/`discoveries` client-side via `map-to-items.ts`'s `filterByFameScore` against each lane's value before mapping/rendering each lane — the data-pipeline's output floor is already the full `specialist` superset, so this is pure filtering, no re-ranking.
- **The Year Axis is plain HTML/CSS, not SVG/D3** — the only piece of `widgets/timeline-canvas/` that isn't. Its tick marks (`.ruler` in `YearAxis.module.css`) are three layered repeating CSS `linear-gradient` backgrounds — year (thinnest), decade, century (tallest, drawn on top since layers stack in first-listed-wins order) — with no per-tick DOM node at all, so unlike every other lane, tick-mark cost is ~flat regardless of the scrollable width and needs no viewport-windowing. Spacing/phase are CSS custom properties (`--year-tick-px`/`--decade-tick-px`/`--century-tick-px`/`--century-tick-offset-px`) computed once per render in `YearAxis.tsx` from `pixelsPerYear` — decades always tile from x=0 with no offset (`PAN_MIN_DATE`'s year, -2750, happens to be a decade multiple) but centuries don't, so `options.ts`'s `phaseOffsetYears`-derived `DECADE_TICK_PHASE_OFFSET_YEARS`/`CENTURY_TICK_PHASE_OFFSET_YEARS` correct for that generically rather than assuming 0. Below the ruler, decade-number labels are a small plain positioned `<span>` list (`.map()`, not a D3 join — there's no per-item enter/exit choreography to justify one) **windowed to the visible scroll range** (`TimelineCanvas.tsx` tracks live `scrollLeft` via a `requestAnimationFrame`-throttled `scroll` listener on the shared container, derives `visibleStartYear`/`visibleEndYear` — viewport + `VIEWPORT_BUFFER_RATIO` (50%) padding — and passes them to `YearAxis`); decade labels are omitted entirely (not just hidden) below `MIN_DECADE_LABEL_SPACING_PX` (40px) of actual on-screen decade spacing, to avoid collision at low zoom, while century labels (10x further apart) are never gated. `TimelineCanvas.tsx`'s `.scrollContainer` also carries a faint full-height decade gridline (same CSS-gradient technique, `--decade-gridline-px`/`--decade-gridline-offset-px`) spanning all four lanes, so content visually aligns to decades without a per-line DOM cost either. This progressively replaced an SVG/D3-rendered axis (first d3's adaptive `axisBottom`, then a fixed-step D3 join) whose one-DOM-node-per-tick cost — sized off the *entire* scrollable width regardless of scroll position — profiling traced to most of initial-load LCP (~2s of a ~5.9s dev-server LCP; see the perf investigation this superseded). The axis's position (between People and Wars & Conflicts, not sticky/fixed) is unchanged; `format-year.ts`'s `centuryBoundariesInRange` is no longer used by `YearAxis` (century *ticks* are now a plain `year % 100 === 0` check) but is kept — still covered by its own tests — since nothing else currently needs it removed.
- Wars & Conflicts and Events & Inventions render directly off `wars.json` (`WarsAndConflictsEntry[]`, a `War | WarEvent` union — see the date-handling bullet above) and `discoveries.json` (`Discovery[]`), each pre-split and lane-scoped by the data-pipeline — `map-to-items.ts` no longer filters by category to route between the two lanes, it just maps each array 1:1. `mapWars` renders a range line for a `War` (narrowed via `"period" in entry`, since `War`/`WarEvent` are structurally disjoint rather than carrying a `kind` tag), a point for a `WarEvent` (`discoveries.json` rows are always a `PointInTime`, so `mapDiscoveries` is always points). The People lane's `mapPeople` keys its fill off `person.occupationDomain` (not `person.category`); Wars/Events key off `category` — both provisionally inlined hex (`DOMAIN_COLORS`/`CATEGORY_COLORS` in `options.ts`) pending Unit 5's real CSS custom properties — the lane CSS Modules' own label/background fills (e.g. `PeopleLane.module.css`'s `.name`, `TimelineCanvas.module.css`'s `.scrollContainer` background) are inlined hex for the same reason, tracked under the same ticket 05.
- A person's `reignPeriods` render as their own thinner rounded-cap accent line directly below their lifespan line, same row, same color (`REIGN_LINE_COLOR`) — plain layout math (same `xScale`, `options.ts`'s `reignLineCenterYForRow` derived from the row's own `personLineCenterYForRow`), no vis-timeline-style subgroup/stacking trick needed.
- People's lifespan lines carry their label *above* the line, left-aligned to its start (`options.ts`'s `personLabelYForRow`/`personLineCenterYForRow`/`personLaneHeight`) — the label's own text color is a fixed dark neutral (`PeopleLane.module.css`'s `.name`, not per-item), unlike Wars & Conflicts (both its range line and point dot) and Events & Inventions (point dot), which carry their label *below* the marker instead (`labelYForRow`/`markerLaneHeight`), centered under it, with the label's fill set per-item to match the marker's own category color. Every marker in the below-marker lanes sits at the same fixed `MARKER_CENTER_Y` — right at the top of its lane, so a marker's x-position always reads directly against the shared YearAxis above — rather than moving to a vertical band per row like People's lines do; a colliding item instead gets a lower label tier (one `MARKER_ROW_PITCH` step per row), pushing just its own label further down while its marker stays put. There are no connecting stems in either treatment — a label's row/tier is purely a y-offset, with nothing drawn between it and its line/dot.
- `assignRows` (in `map-to-items.ts`) is the shared greedy interval-graph row-stacking function: sort by `startYear`, place in the first row that clears with a gap to spare (`MIN_ROW_GAP_YEARS` by default), else open a new row. All three lanes now reuse it in pixel-space (each lane's own much smaller `MIN_ROW_GAP_PX` gap) rather than year-space, since a label can be far wider on screen than its underlying date range (or, for a point, has no range at all) — the row/tier is sized off each item's estimated pixel footprint (`options.ts`'s `estimateLabelWidthPx`, unioned with the line/marker's own pixel span), not its years. People's label is left-aligned above its line's start, so its pixel interval only needs to extend rightward past the line's own end when the label is wider; Wars & Conflicts/Events & Inventions' labels are centered below their marker, so their interval extends symmetrically either side.
- Each lane's D3 join uses literal (non-CSS-Module) marker classes like `d3-line`/`d3-dot`/`d3-name`/`d3-reign-line` for `selectAll`/`data`/`join` matching — CSS-Module classes ride alongside purely for styling and must never be used as join selectors. `d3-line` is shared by both People's lifespan lines and Wars & Conflicts' range lines (both a Period, same shape) — code querying it (including tests) must scope to the owning lane's `<svg>` rather than assuming one per page.
- Tooltips render as a native SVG `<title>` child element (real DOM, hover-triggered by the browser), not a component-level `title` attribute.
- Wheel-zoom is not wired; the dedicated +/- buttons are the only zoom control. Panning (horizontal, on the shared container) is native browser scroll plus a mouse-drag handler (`TimelineCanvas.tsx`'s `handlePointerDown`/`handlePointerMove`/`endDrag`, gated to `pointerType === 'mouse'` so it doesn't double-handle touch, which already gets native swipe-to-scroll for free); per-lane row overflow (vertical, on each lane) is native scroll only.

### Data and Storage

- Filter/selection/viewport state is in-memory only, owned by its feature slice.

### File Organization

`src/`, by mini-FSD layer: `shared/lib` (`today()`, the one live `Temporal.PlainDate` read the rendering path needs; `format-year.ts`'s BCE/CE display formatting, including month-aware `formatYearMonth`), `shared/config` (zoom/viewport constants and the fame-score filter bounds/defaults in `viewport.ts`, plus `OccupationDomain` color/label tables in `occupation-domain-colors.ts` — shared between `widgets/timeline-canvas` and `widgets/sidebar`, re-exported via a barrel `index.ts`), `shared/types` (re-exports from `packages/shared-types`), `shared/ui` (generic primitives); `features/filter-by-fame-score` (`model/useFameScoreFilters` session-only state hook, `ui/FameScoreFilters` presentational controls — state is called once in `app/` and threaded to both `widgets/sidebar` and `widgets/timeline-canvas` as props), `features/filter-by-occupation`, `features/filter-by-region`, `features/select-timeline-entity`, `features/filter-timeline-entities` (combines the two remaining filters via AND); `widgets/timeline-canvas`, `widgets/sidebar` (Legend + Filters, always visible alongside `TimelineCanvas`), `widgets/filter-bar`, `widgets/detail-panel`; `app/` (entry point, composes the widgets and owns the one cross-widget piece of state, the fame-score filter values).
