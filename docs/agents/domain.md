# Domain Docs

Before exploring, read the root glossary and the relevant ADRs under `docs/adr/` or `packages/<package>/docs/adr/`. Proceed silently if a file is absent. [Glossary](../../GLOSSARY.md) · [Root ADRs](../adr/)

Use established domain terms in issue titles, tests and proposals. Reconsider unfamiliar wording against the glossary. Bring genuine gaps to `/domain-modeling` when a term needs resolving.

If a proposal conflicts with an ADR, name the decision and explain why it merits reopening.
