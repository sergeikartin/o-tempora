# Product Scope

<!-- Product scope and UX decisions. Read before making a scope or UX call. -->

Visualize human history and global events in context: an interactive timeline of world history (~800 BCE-present, extendable to 3000 BCE), inspired by Map of Contemporaries / Wait But Why's "Horizontal History." Three lanes: **People** (birth-death range bars), **Conflicts** (wars as range bars, single-date conflicts as points, optionally nested under a parent Conflict via `parentId` — see `CONTEXT.md`'s **Container**), **Milestones** (points, or range bars for a milestone with a known end date, e.g. a pandemic). All data hardcoded ahead of time — People from Pantheon 2.0, Conflicts and Milestones each a hand-curated list backfilled with a batched Wikidata SPARQL enrichment pass — no accounts, no editing, no live fetching.

**Goals:** help users see whose lives overlapped in time; make the shape of history visually intuitive; no login/setup friction; ship a well-scoped v1 (connections, comparison mode, and a map view are deferred, not abandoned).

**Core flow:** lands on the landing page, then opens the timeline on 1740–1860 at the default Detail Level (`Mainstream`) → pan/zoom map-style (no "see all history" view) → a 4-position Detail Level switch (`Legendary`/`Mainstream`/`Specialized`/`Deep Cut`) gates entity density by fame directly (Pantheon's HPI for People, a blended Wikidata-sitelinks/pageviews score for Conflicts/Milestones — see `packages/web/docs/adr/0003-manual-fame-filter-replaces-zoom-tier.md`, `docs/adr/0006-detail-level-merges-data-depth-and-payload-tier.md`) — zoom itself no longer affects density — plus occupation/region filters (combined with AND) → click an entry for its detail panel (name, dates, description, Wikipedia link). Picking an entity — by click or Search — is shareable as an **Entity Link** (`?e=<slug>`): opening one pans to the entity and shows its panel at whichever Detail Level it needs, and Back closes the panel.

**In scope:** pan/zoom timeline, three lanes, 4-position Detail Level switch (not zoom-coupled), occupation filter, region filter (tag-based, not a map), click-to-open detail panel, **English and Russian** (one build, locale resolved at runtime from the URL — `/` and `/ru/` for the landing page, `/timeline/` and `/ru/timeline/` for the timeline, no inline bilingual display; a language link between each page and its sibling — see `.scratch/russian-localization/spec.md`, `packages/web/docs/adr/0009-runtime-locale-switch-replaces-per-locale-builds.md`, and `docs/deployment.md`), a **landing page** at `/` and `/ru/` (headline, a one-line pitch, a switchable set of hand-picked curious overlaps each stated in a sentence and drawn as marks on a short axis with Entity Links into the timeline, one call-to-action that opens the shown overlap's first mark on the timeline, a footer crediting the data sources with links to the data license and the source repo, no datasets or timeline code loaded until the visitor shows intent to open it; `docs/adr/0007-landing-and-timeline-split-into-four-routes.md`), **a baseline mobile/touch experience** down to ~360-390px phone widths, both orientations (collapsible filter drawer, bottom-sheet detail panel, pinch-to-zoom in place of the desktop zoom buttons, Minimap omitted — see `.scratch/mobile-responsive-layout/spec.md`), a visitor-opened **Help panel** (`?` key or the sidebar footer link; how to travel, read marks and colors, and use Detail Level — no tour or coach marks) with lane captions drawn in the canvas margin, an **About panel** (code license, data sourcing/attribution — required in-app since CC BY-SA 4.0's attribution clause reaches wherever the data is shared, not just the source repo).

**Out of scope (v1):** connections between people, a literal map view, any write functionality, live data fetching, search outside the current Detail Level's fame-score floor, rich per-entry content (video/notes/articles), any language beyond English/Russian, inline bilingual (side-by-side) display within one session, any URL state beyond the Entity Link (viewport, Detail Level and filters never reach the URL). The raw per-lane numeric fame-score inputs are a dev-console-only escape hatch, not production UI (`docs/adr/0006-detail-level-merges-data-depth-and-payload-tier.md`).

**Success criteria:** smooth pan/zoom with the full default dataset; correct stacking in dense periods; filters/Detail Level update without lag; accurate detail panels; correct BCE/CE rendering; dataset populated for the top 200 people plus a comparable set of events before launch. The Russian dataset has the identical entity set as English — inclusion (which people/conflicts/milestones appear at all) is decided once, off the English fetch results, so "top 200 people" is not a separately-met bar per language; per-field Russian completeness (name/tagline/description) is whatever Wikidata's/ru.wikipedia.org's own coverage resolves, with English fallback per field wherever it doesn't.
