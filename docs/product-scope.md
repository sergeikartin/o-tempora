# Product Scope

<!-- Product scope and UX decisions. Read before making a scope or UX call. -->

Visualize human history and global events in context: a read-only, zoomable visualization of world history (~800 BCE-present, extendable to 3000 BCE), inspired by Map of Contemporaries / Wait But Why's "Horizontal History." Three lanes: **People** (birth-death range bars), **Conflicts** (wars as range bars, single-date conflicts as points, optionally nested under a parent Conflict via `parentId` — see `CONTEXT.md`'s **Container**), **Milestones** (points, or range bars for a milestone with a known end date, e.g. a pandemic). All data hardcoded ahead of time — People from Pantheon 2.0, Conflicts and Milestones each a hand-curated list backfilled with a batched Wikidata SPARQL enrichment pass — no accounts, no editing, no live fetching.

**Goals:** help users see whose lives overlapped in time; make the shape of history visually intuitive; no login/setup friction; ship a well-scoped v1 (connections, comparison mode, and a map view are deferred, not abandoned).

**Core flow:** opens on the 1800s (100-year window) at the default Detail Level (`Mainstream`) → pan/zoom map-style (no "see all history" view) → a 4-position Detail Level switch (`Legendary`/`Mainstream`/`Specialized`/`Deep Cut`) gates entity density by fame directly (Pantheon's HPI for People, a blended Wikidata-sitelinks/pageviews score for Conflicts/Milestones — see `packages/web/docs/adr/0003-manual-fame-filter-replaces-zoom-tier.md`, `docs/adr/0006-detail-level-merges-data-depth-and-payload-tier.md`) — zoom itself no longer affects density — plus occupation/region filters (combined with AND) → click an entry for a tooltip (name, dates, description, Wikipedia link).

**In scope:** pan/zoom timeline, three lanes, 4-position Detail Level switch (not zoom-coupled), occupation filter, region filter (tag-based, not a map), click-to-view tooltip, read-only, **English and Russian** (one build, locale resolved at runtime from the URL — `/` and `/ru/`, no inline bilingual display; home-level link between them — see `.scratch/russian-localization/spec.md`, `packages/web/docs/adr/0009-runtime-locale-switch-replaces-per-locale-builds.md`, and `docs/deployment.md`), **a baseline mobile/touch experience** down to ~360-390px phone widths, both orientations (collapsible filter drawer, bottom-sheet detail panel, pinch-to-zoom in place of the desktop zoom buttons, Minimap omitted — see `.scratch/mobile-responsive-layout/spec.md`), an **About panel** (code license, data sourcing/attribution — required in-app since CC BY-SA 4.0's attribution clause reaches wherever the data is shared, not just the source repo).

**Out of scope (v1):** connections between people, a literal map view, any write functionality, live data fetching, search outside the current Detail Level's fame-score floor, rich per-entry content (video/notes/articles), any language beyond English/Russian, inline bilingual (side-by-side) display within one session, deep-linking the language switcher to preserve viewport/selection. The raw per-lane numeric fame-score inputs are a dev-console-only escape hatch, not production UI (`docs/adr/0006-detail-level-merges-data-depth-and-payload-tier.md`).

**Success criteria:** smooth pan/zoom with the full default dataset; correct stacking in dense periods; filters/Detail Level update without lag; accurate detail tooltips; correct BCE/CE rendering; dataset populated for the top 200 people plus a comparable set of events before launch. The Russian build ships the identical entity set as English — inclusion (which people/conflicts/milestones appear at all) is decided once, off the English fetch results, so "top 200 people" is not a separately-met bar per language; per-field Russian completeness (name/tagline/description) is whatever Wikidata's/ru.wikipedia.org's own coverage resolves, with English fallback per field wherever it doesn't.
